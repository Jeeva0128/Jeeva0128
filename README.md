## Featured Project
 
<div align="center">
### Predictive Auto-Scaling and Load-Balancing Framework
**Final Year Project — B.Tech Information Technology**
 
![Status](https://img.shields.io/badge/Status-In%20Progress-yellow?style=flat-square)
![Type](https://img.shields.io/badge/Type-Final%20Year%20Project-blue?style=flat-square)
 
</div>
<details open>
<summary><b>Project Overview</b></summary>
<br>
A cloud infrastructure project focused on designing a framework that predicts application load and dynamically adjusts compute resources and traffic distribution ahead of demand spikes, rather than reacting after they occur.
 
</details>
<details>
<summary><b>Problem Statement</b></summary>
<br>
Traditional auto-scaling reacts to load *after* thresholds are breached, which can cause latency spikes and degraded user experience during sudden traffic surges. This project explores a predictive approach to scaling decisions.
 
</details>
<details>
<summary><b>Objectives</b></summary>
<br>
- Analyze traffic and resource utilization patterns to anticipate load changes
- Design a scaling framework that acts proactively rather than reactively
- Distribute incoming traffic efficiently across available compute resources
- Evaluate the framework's behavior under simulated variable load
</details>
<details>
<summary><b>Features (Planned)</b></summary>
<br>
- Load prediction based on historical and real-time metrics
- Automated scaling triggers integrated with cloud compute resources
- Load-balancing logic to distribute traffic across instances
- Logging and monitoring of scaling events for evaluation
</details>
<details>
<summary><b>Architecture (Planned)</b></summary>
<br>
- Compute layer provisioned and managed on AWS
- Load balancer distributing incoming requests across instances
- Monitoring/metrics layer feeding data into the prediction logic
- Automation scripts handling scale-out and scale-in actions
</details>
<details>
<summary><b>Expected Technologies</b></summary>
<br>
- **Linux Usage:** Server configuration, process monitoring, shell scripting for automation
- **AWS Services:** EC2, Auto Scaling Groups, Elastic Load Balancing, CloudWatch
- **Languages:** Python for prediction logic, Bash for automation scripts
</details>
<details>
<summary><b>Future Scope</b></summary>
<br>
- Extending the framework with container-based workloads (Docker/Kubernetes)
- Incorporating Infrastructure as Code (Terraform) for reproducible environments
- Adding cost-optimization logic alongside performance-based scaling
</details>
> **Status:** This project is currently in the design and development phase as part of my final year coursework. No deployment claims are made at this stage.
